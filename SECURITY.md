# Security policy

## Supported versions

Until the first stable release, security fixes are provided on the latest release only.

## Reporting a vulnerability

Please do not open a public issue for a vulnerability that could put users or tested systems at risk. Use GitHub's **Security** tab and select **Report a vulnerability** to start a private advisory. Include the affected version, reproduction steps using a local test system, impact, and a suggested fix if available.

Maintainers should acknowledge complete reports within seven days and coordinate a fix and disclosure timeline with the reporter. Never include live credentials, tokens, or third-party target data in a report.

## Scope

Reports about bypassing the tool's authorization acknowledgement are not, by themselves, security vulnerabilities; it is a deliberate operator acknowledgement rather than an access-control boundary. Secret or token disclosure by the tool, unsafe redirect behavior, dependency compromise, or unintended network access are in scope.
